# 2.8 平台衔接说明 / Platform handoff

## 2.8.1 补充 / 2.8.1 follow-up

主题升至 2.8.1，加载器升至 1.3.1；Codex 精确 app/package/x64 检查不变。`engine/runtime.mjs` 仅增加内部 `readLauncherState`，为启动及控制文件替换的短暂缺失/删除等待提供有界重试；损坏内容和其他错误仍立即失败。`管理主题.ps1` 复用已验证窗口，只在最小化时恢复，并在 Start/Resume 拒绝另一独立主实例。同一 Windows 客户端的多窗口发现、逐窗恢复、独立 heartbeat 和共享选择事务继续保留。

此次共享差异适合以后按函数逐项审阅：内部读 helper 不新增公共接口或配置字段；窗口唤回及主实例检查仍属于 Windows 启动器。`theme/adapter.json` 同步主题版本；`theme/renderer.js` 除版本常量外，将 Codex 首页纸箱贴纸锚定到 `ctx.composerColumn.top`，把输入框上方工具栏计入避让，保留原生 Codex 图标。六款素材、CSS 和人物取景不变。新增全局/项目首页、工具栏增高和暂停恢复模拟；48/48 页面模拟已通过，详见验证记录。对应测试与版本文档同步，Mac 运行代码未混入，也未修改 PR #2。下文是 2.8.0 的历史衔接说明，其中“runtime 未改动”等表述仅适用于该历史版本。

Theme 2.8.1 uses loader 1.3.1 with the same exact Codex app/package/x64 checks. The only shared runtime addition is the internal `readLauncherState` helper, which retries brief missing/delete-pending errors during startup and control-file replacement. Malformed data and other errors still fail immediately. The Windows manager reuses a verified window, restores it only when minimized, and rejects another independent main instance during Start/Resume. Per-window discovery, recovery, heartbeats and shared selection transactions remain intact.

Future Mac work can review the helper as a small function-level change; it adds no public interface or configuration field. Window activation and main-instance checks stay in the Windows launcher. The adapter synchronizes the theme version. Alongside its version constant, the renderer anchors the Codex home box sticker to `ctx.composerColumn.top` so it clears the toolbar above the composer while preserving the native Codex icon. Artwork, CSS and character framing remain unchanged. Added simulations cover global/project home, toolbar growth and pause/resume cleanup; all 48 renderer simulations passed; see the validation record. Tests and version documentation are updated; Mac runtime code and PR #2 are untouched. The sections below describe the historical 2.8.0 handoff, so their unchanged-runtime statements apply to that version only.

首页位置补充：低位首页使用可恢复的输入列纵向平移，最多 96 个 CSS 像素，并受可用高度与标题顶部余量限制。标题及纸箱随输入区域上移；进入对话时先恢复列位置，再计算底部阅读裁切。原生菜单打开时保持输入列和标题的位移，只隐藏装饰贴纸；关闭菜单后恢复贴纸，避免整个首页跳动。四档窗口模拟确认菜单开关前后控件坐标和人物边界不变。未新增 CSS、配置或公共接口。

Home positioning follow-up: low home layouts use a reversible composer-column translation, capped at 96 CSS pixels and constrained by viewport height and heading clearance. The heading and mascot follow the composer. Conversation navigation restores the column before measuring the reader clip. Native menus leave the composer and heading offsets in place while hiding decorative stickers. Closing the menu restores the stickers without shifting the home layout. Four viewport simulations confirm unchanged controls and artwork bounds across menu open/close. No CSS, configuration or public API was added.

## 2.8.0 历史说明 / Historical 2.8.0 notes

2.8.0 Windows 版适配 Codex **26.1023.51421 / 26.1023.6621.0**，x64。加载器保持 **1.3.0**。以已发布 2.7.0 的文件树为基线，不混入实验性 Mac 运行代码。

10 月 29 日继续沿用已修好的 2.8.0，更新精确版本绑定、测试和文档。随后实机补齐 renderer 的底栏绘制范围：通用选择器仍限于输入框 host，仅精确的原生 `_background_18hic_2` 背景节点扩展至同一个 `.thread-scroll-container`，以处理 transcript 内的兄弟绘制分支；保留原来的几何筛选及清理机制。CSS 和 runtime 未新增改动。下文说明相对于已发布 2.7.0 的累计差异。

共享文件的局部改动：`theme/renderer.js` 更新主题版本常量，识别移到活动页标题栏的首页模式控件，允许无模式切换的首页标题，并识别新版底栏的纯绘制节点；`theme/theme.css` 去掉 DIL 表格内层滚动区的多余横向留白。标题栏只移动模式按钮组，不移动其他控件；正文、输入框本体及未知页面保持原有保护。`theme/adapter.json` 更新 Windows 精确 app/package 绑定及检查日期。

`engine/runtime.mjs`、`engine/wallpaper-store.mjs`、PowerShell 启动和身份检查、六款素材、配色与取景配置保持逐字节一致。多窗口发现、逐窗恢复、独立 heartbeat、共享选择事务、动态 Chat 和图片查看器逻辑均保留。`tools/test-renderer.mjs` 补充首页、底栏、嵌套表格、横向滚动与清理检查；未来 Mac 整合应按实际 DOM 核对这些局部选择器，不整文件覆盖。

继续保留 greppro 提供的平台打包边界思路：源码可共存，Windows 路径不执行 Mac 模块；最终 Windows 包排除 Mac adapter、启动器及专属文件。对应负例和解压测试仍保留。谢谢 greppro 在独立启动器、身份校验、归档 Chat 和打包拆分上的工作。

PR #2 于 2026-10-29 核对仍为 Draft，head 为 `d91113b88ddecb831f23d0b359db7018a8355f5d`。本轮未修改 PR，也没有覆盖本地 Mac 整合成果。将来整合时应分别保留 Windows app/package/x64 与 Mac app/build/arm64 检查；不能直接把 Windows adapter 覆盖到 Mac，也不要因 Mac 单窗限制而缩减 Windows 多窗口。

运行时版本、配置格式、壁纸 ID、选择存储与控制接口不变。后续 Mac 共同开发可以基于这份小范围差异继续；当前不声明 Mac 原生验收或正式支持。检查范围见[验证记录](验证记录.md)。

## English

The historical 2.8.0 Windows release targets Codex **26.1023.51421 / package 26.1023.6621.0**, x64, retaining loader **1.3.0** and the published 2.7.0 file tree as its baseline.

The October 29 update changes exact compatibility bindings, tests and documentation. Native testing then adds one local renderer fix: generic paint lookup stays inside the composer host, while the exact native `_background_18hic_2` selector also covers sibling transcript paint within the same `.thread-scroll-container`. Existing geometry checks and cleanup remain in place. CSS and runtime have no additional changes. The following describes cumulative differences from published 2.7.0.

The shared renderer updates its strict theme-version constant, locates home mode controls in the active page titlebar, allows greetings without a mode toggle, and recognizes the new paint-only footer layer. It moves only the mode button group, not neighboring header controls. Theme CSS removes the excess inset from DIL table scroll viewports. The Windows adapter receives exact build metadata. Renderer fixtures cover these changes, scrolling and cleanup; future Mac integration should check the local selectors against its DOM rather than replace whole files.

Runtime, wallpaper store, PowerShell launch/identity guards, artwork, colors and framing remain byte-identical. Multiwindow discovery, per-window recovery, heartbeats, shared selection transactions, dynamic Chat and image-preview handling remain intact.

We retain the platform boundary work informed by greppro: platform sources may coexist, Windows must not execute Mac-only dependencies, and the final Windows ZIP excludes Mac-specific files. Negative dependency probes and extracted-package checks remain in place. Thanks to greppro for the separate Mac launcher, identity checks, archived Chat support and packaging work.

PR #2 was still Draft at head `d91113b88ddecb831f23d0b359db7018a8355f5d` on 2026-10-29. Neither the PR nor the local experimental integration was changed. Future integration must preserve separate app/build/architecture checks and keep Windows multiwindow support. No native Mac acceptance is claimed. See [validation](en/validation.md).

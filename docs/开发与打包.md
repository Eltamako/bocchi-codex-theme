# 开发与打包

源码包不包含 `engine/node.exe`。从同版本 Windows 完整包取出这个文件，放回源码对应位置；SHA256 必须与 `release.json` 一致。Node 许可保存在 `engine/LICENSE-Node.txt`。

## 本地检查

在源码根目录的 PowerShell 中执行：

```powershell
& .\engine\node.exe --preserve-symlinks --preserve-symlinks-main .\tools\check-assets.mjs
& .\engine\node.exe --preserve-symlinks --preserve-symlinks-main --test .\tests\wallpaper-store.test.mjs .\tests\environment.test.mjs .\tests\language.test.mjs .\tests\runtime-install.test.mjs .\tests\runtime-recovery.test.mjs
& .\tests\shortcut.test.ps1
& .\tests\instance-guard.test.ps1
& .\tests\readiness.test.ps1
& .\tests\startup.test.ps1
& .\tests\duplicate-start.test.ps1
& .\tests\installation-guard.test.ps1
& .\tests\termination-behavior.test.ps1
& .\安装.ps1 -CheckOnly
```

前面几项使用包内素材及隔离测试目录，不连接客户端；快捷方式测试只写测试目录。最后一项只读核对客户端版本，不创建配置或桌面入口。目录联接检查如果被系统权限拦截，会明确显示跳过，不应算作通过。

中英文文案集中在 `theme/messages.json`，请保持两种语言的键与占位符一致。PowerShell 文件使用 UTF-8 BOM，兼容 Windows PowerShell 5.1；命令入口使用 UTF-8 与代码页 65001。

## 修改和打包

运行文件在 `theme/renderer.js`、`theme/theme.css` 和 `engine/`，壁纸参数在 `theme/wallpapers.json`。六个固定 ID 不变；环境图通过 `nativeSize`、`mainRect` 与主图对齐。建议在独立目录编辑，保留可恢复的上一版本。

1. 完成改动和检查；记录实际覆盖的页面及未验证范围。
2. 更新 `release.json`、`theme/adapter.json`、README、CHANGELOG 和素材清单。客户端版本只有经过适配后才调整。
3. 更新源码校验，再构建 Windows 完整包：

```powershell
& .\engine\node.exe --preserve-symlinks --preserve-symlinks-main .\tools\update-checksums.mjs
& .\tools\build-release.ps1 -NodePath .\engine\node.exe
```

输出位于 `dist/`。已有同名压缩包时脚本会停止；先将旧包归档，勿覆盖已发布附件。源码包按同一 `CHECKSUMS.sha256` 清单打包，只省略运行文件。

构建只读取清单内文件，排除 `.local`、`installation.json`、日志、快捷方式、测试产物和 Git 历史。不要把运行过的整个文件夹直接压缩上传。`CHECKSUMS.sha256` 不包含自身哈希；Release 的 `SHA256SUMS.txt` 记录各压缩包哈希。

发布步骤见 [GitHub 发布与版本更新](GitHub发布步骤.md)。

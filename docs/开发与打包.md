# 开发与打包

## 获取运行环境

源码包不包含 `engine/node.exe`。从同版本 Windows 完整包取出这个文件，放回源码对应位置即可；其 SHA256 必须与 `release.json` 一致。完整包保存了 Node.js 的完整许可。

这里选择固定运行文件，是为了让启动器、回执与恢复逻辑使用同一套运行环境。更换 Node 版本时，应重新检查运行行为和校验记录。

## 本地检查

在源码根目录的 PowerShell 中执行：

```powershell
& .engine
ode.exe --preserve-symlinks --preserve-symlinks-main .	oolscheck-assets.mjs
& .engine
ode.exe --preserve-symlinks --preserve-symlinks-main --test .	estswallpaper-store.test.mjs
& .安装.ps1 -CheckOnly
```

前两项是素材与隔离模块检查，不连接客户端。最后一项读取已安装客户端版本，不创建配置或快捷方式。

首次配置但不需要桌面入口时，可以执行 `& .安装.ps1 -NoShortcuts`。它仍会在当前包内创建本机配置，不会启动客户端。

## 构建完整包

```powershell
& .	oolsuild-release.ps1 -NodePath .engine
ode.exe
```

脚本会核对 Node 与源码文件校验值，再生成 `dist/Bocchi-Codex-Theme-2.3.0-public.1-windows-x64.zip`。目标已存在时会停止，便于保留旧包。

修改源码后，运行 `& .\engine\node.exe --preserve-symlinks --preserve-symlinks-main .\tools\update-checksums.mjs` 更新 `CHECKSUMS.sha256`；文件清单本身不包含自己的哈希。构建按该清单打包，`.local`、本机配置及测试产物不会进入分发包。不要把运行过的整个目录重新压缩后直接上传。

## 编辑视觉

主题的样式在 `theme/theme.css`，取景参数在 `theme/wallpapers.json`。四个固定 ID 与图片相对路径是加载协议的一部分，修改时保持对应关系。阅读遮罩应覆盖可视高度，人物保护区域避开脸、手、脚和乐器。

运行中的文件变化可能触发重新加载。建议在独立副本里编辑，先暂停主题，再替换素材和检查，最后恢复。版本号和页面标记只有经过新客户端验证后才更新。

## 提交到仓库

仓库内容对应源码包中的文件。请保留 `.gitignore`：它排除了 `.local`、`installation.json`、Node 二进制、日志、桌面快捷方式与测试产物。真实截图若包含聊天、目录或用户名，分享前先去掉这些内容。
